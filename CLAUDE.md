# CLAUDE.md — HUSH project memory

HUSH is an original PSP homebrew game and generative music release by **Synth Centric**:
free flight through the night city of Vesper (2146) in a small VTOL craft, the Moth,
while a real-time generative synthesizer composes music from the world and the player.
Modes: **PATROL** (12 missions), **DRIFT** (free flight), **SIGNAL CONSOLE** (the synth).

## Hard constraints
- Target: original PSP-1000 (333 MHz Allegrex, 32 MB RAM / ~24 MB user, fixed-function GE, 480x272).
- C only (gnu11), PSPSDK libGU/libGUM, `sceAudio`, `sceIo`/newlib stdio. Single-precision floats only.
- 30 fps target; audio must never starve (dedicated thread, priority 0x10, no allocation in the audio path).
- Music engine and game logic are **platform independent** (`src/audio`, `src/game`, `src/core`) and are
  compiled unchanged into the host tools/tests. Never put PSP calls in those directories.
- Determinism: composer, theory, profiles, music_engine, world and traffic are compiled with strict IEEE
  (`-fno-fast-math -ffp-contract=off`, host also `-fsingle-precision-constant`). **Never put two RNG
  draws in one expression or argument list** (C evaluation order is unspecified; MIPS and x86 differ —
  this caused a real cross-platform divergence once). Draw into locals in a fixed order.
- Mission-critical places are explicit in `src/game/world.c` and reserved before procedural fill.
- Textures for the GE must be power-of-two sized. `sceGuSetDither` must not be called with NULL.
- Handedness: right-handed world, Y up; screen-right looking along +Z is -X. `craft_right()` = forward x up;
  positive yaw input = turn right = yaw decreases; compass heading = -yaw. Tests enforce this.
- Save format: append new fields at the end of the payload and read them only `if (r.n < r.len)` so old saves load.
- Display list is 1 MB per frame: cap any per-frame dynamic geometry (crowd capped at 40 near + 80 far figures).
- Colours on the GE are ABGR (`RGBA()` macro in gfx.h does the packing). `sceGuDepthMask(GU_TRUE)` *disables* depth writes.

## Layout
- `src/core` — math (`hmath.h`), PCG32 RNG + FNV hash (`rng.h`).
- `src/audio` — DSP (wavetables, SVF, envelopes), voices, FX, theory, composer (6 layers), engine, presets, SFX.
- `src/game` — world generation + collision, flight + cameras, traffic, weather, missions (+ data), progress/saves, env bridge, autopilot.
- `src/render` — PSP-only: textures, chunked city meshes, lights, sky, effects, Moth model.
- `src/ui` — PSP-only: app state, gameplay session, HUD, menus, Signal Console.
- `src/platform/psp` — entry point/main loop (+ HUSH_AUTOTEST scripts), GU wrapper, audio thread, input, save I/O.
- `src/assets/generated` — fonts, logo, billboards (generated by `tools/asset-generation/gen_assets.py`; committed).
- `tools/audio-renderer/hush_render.c` — host WAV renderer. `tests/test_main.c` — host test suite.
- `tools/validation/run_ppsspp.sh` — emulator validation. `tools/release.sh` — packaging.

## Commands
```
export PSPDEV=/usr/local/pspdev PATH=$PATH:$PSPDEV/bin   # Makefile sets these itself
make                 # build/psp/EBOOT.PBP
make test            # host suite (quick, ~2 min); make test-full adds a 30-min audio run
make autotest autotest-campaign && sh tools/validation/run_ppsspp.sh   # PPSSPP runtime validation
./build/host/hush-render --seed 4817 --preset drift --minutes 10 --output out.wav
make release         # release/ folder, zips, checksums, report
```
Toolchain: prebuilt pspdev release (github.com/pspdev/pspdev, "latest") unpacked to /usr/local/pspdev.
Emulator: PPSSPPHeadless built from hrydgard/ppsspp (needs SDL3 + SDL3_ttf built from source on Ubuntu 24.04).

## Architecture notes
- Audio: engine renders at 22.05 kHz on PSP (44.1 kHz on host), thread upsamples x2 to the 44.1 kHz channel.
  All composition decisions happen per 16th-note step and are independent of sample rate.
- Game → music: `env_bridge.c` maps altitude, speed, district, rain, fog, pursuit, traffic, enclosure,
  scanner, signal and landmark proximity into `MusicEnv`; the composer smooths per step.
- Params/env reach the audio thread through a seqlock mailbox (`hush_music_set_params/env`).
- City: 8x8 chunks per district, sorted by texture, facades split into ≤34 m panels (GE near-plane issue).

## Status (see docs/TESTING.md for evidence)
Implemented and validated in PPSSPP: all modes, 4 districts, 12 missions (all completed by the autopilot
in the PSP build), saves, Signal Console, 5 sonic landmarks, weather, traffic, 3 cameras, street level
(shopfronts, neon, street traffic, pedestrians), story layer (prologue, operator's log, case file, chatter),
face-button (default) and classic control schemes.
Not done: real-hardware testing; PDF manual depends on Chromium being present.

## Known limitations
- PPSSPP timings (fps, CPU ms, audio load) come from the emulated clock and are not hardware measurements.
- No proper XMB savedata (PARAM.SFO savedata dialog); saves are files beside the EBOOT.
